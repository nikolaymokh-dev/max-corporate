# Бриф: корпоративный аккаунт в MAX через Bot API

> Документ для того, кто будет запускать и поддерживать проект.
> Сначала прочитайте разделы 1–3 о том, как всё устроено. Потом заполните раздел 5 с вопросами.
> Пока на них нет ответов, код не пишем.

## 1. Что делаем

Один сервис, который ведёт корпоративное присутствие компании в мессенджере MAX. Работает **только через официальный Bot API**: https://dev.max.ru/docs-api. Неофициальные API личного аккаунта не используем, потому что за них блокируют.

Сервис покрывает четыре задачи:

| # | Задача | Что получает компания |
|---|---|---|
| 1 | **Канал компании** | публикация постов (текст, фото, видео, файлы, кнопки), отложенные посты, закрепы, модерация комментариев |
| 2 | **Бот поддержки** | клиент пишет боту, вопрос попадает в рабочую группу операторов, оператор отвечает, ответ уходит клиенту |
| 3 | **Рабочие группы** | уведомления из других систем (сайт, CRM, формы), управление участниками и админами |
| 4 | **Управление через Claude (MCP)** | сотрудник пишет в Claude Code: «опубликуй пост», «что пришло в поддержку за день», «ответь клиенту #42» |

## 2. Как это работает

### Главное ограничение: нужен постоянно включённый сервис

Бот в MAX узнаёт о событиях (новое сообщение, комментарий, нажатие кнопки) одним из двух способов:

- **long-polling.** Сервис сам каждые несколько секунд спрашивает у MAX: «есть новое?». Ему не нужны ни домен, ни входящие соединения.
- **webhook.** MAX сам отправляет событие на HTTPS-адрес сервиса. Это быстрее и надёжнее, но нужен домен с HTTPS.

В обоих случаях события **забирает только один получатель**. Если события не забирать, клиент напишет в поддержку, а его сообщение никто не увидит. Поэтому нужен процесс, который работает **24/7**. Отсюда вопрос «где он будет работать» в разделе 4.

Вторая причина нужна своя база: с июня 2026 MAX убрал метод «список всех чатов бота». Сервис сам запоминает, в какие чаты и каналы добавлен бот. Ещё в базе хранятся обращения клиентов и история переписки.

### Схема

```
                    ┌──────────────────────── MAX ────────────────────────┐
                    │  клиенты      канал компании      рабочие группы    │
                    └──────▲────────────▲───────────────────▲─────────────┘
                           │ Bot API (platform-api2.max.ru) │
                           ▼                                ▼
┌──────────────────────── Сервис (работает 24/7) ────────────────────────────┐
│                                                                            │
│  Приём событий ──► Обработчики:                                            │
│  (polling или      • поддержка: обращение → карточка в группе операторов    │
│   webhook)         • канал: модерация комментариев, публикация по расписанию│
│                    • группы: реестр чатов, команды бота                     │
│                                                                            │
│  База данных: чаты, обращения, переписка, очередь постов, журнал действий  │
│                                                                            │
│  Вход для внешних систем: POST /notify  → сообщение в нужную группу         │
│  MCP-эндпоинт для Claude: /mcp (по токену доступа)                          │
└────────────────────────────────────▲───────────────────────────────────────┘
                                     │ HTTPS + токен
                          Claude Code / Claude Desktop у сотрудника
```

MCP-сервер встроен в сам сервис и доступен по HTTP. Благодаря этому Claude у любого сотрудника видит те же данные, что и бот: обращения, чаты, историю. Ничего не надо копировать на компьютер каждого сотрудника.

### Сценарий поддержки (выбран: операторы отвечают через рабочую группу)

1. Клиент пишет боту. Если сейчас нерабочее время, бот отвечает автоответом.
2. Сервис создаёт обращение `#42` и публикует в группе операторов карточку: имя клиента, текст, вложения и кнопки **«Взять»** и **«Закрыть»**.
3. Оператор отвечает **реплаем на карточку**, и бот отправляет этот текст клиенту от имени компании.
4. Новые сообщения клиента по тому же обращению приходят в группу продолжением.
5. «Закрыть» завершает обращение. Если клиент потом напишет снова, откроется новое обращение.
6. Из Claude можно посмотреть открытые обращения, получить сводку за день и ответить клиенту.

> ⚠️ Это нужно проверить на живом боте до того, как писать код. Видит ли бот в группе **все** сообщения или только адресованные ему (реплаи, упоминания, команды)? От ответа зависит, как оператор будет отвечать: реплаем или командой `/reply 42 текст`.

### Сценарий канала

- Пост готовит человек или Claude. По желанию сначала отправляем его **черновиком в группу согласования** с кнопками «Опубликовать» и «Отклонить».
- Отложенную публикацию MAX API не поддерживает, поэтому её делает сам сервис: хранит очередь постов и публикует их в нужное время.
- Комментарии под постами бот получает в реальном времени. Он может удалять комментарии по стоп-словам или пересылать подозрительные модератору.

## 3. Что умеет и чего не умеет Bot API

**Умеет:** отправлять, редактировать и удалять сообщения; работать с медиа и кнопками (ссылка, callback, запрос контакта или геолокации, мини-приложение); работать с комментариями к постам; закрепы; менять название, описание и иконку чата; управлять участниками и админами; показывать статус «печатает…»; задавать меню команд бота.

**Не умеет:**
- управлять бизнес-профилем, верификацией, карточкой компании и рекламой: это делается только вручную в https://business.max.ru;
- первым написать человеку, который сам не начал диалог с ботом;
- отложенную отправку (сервис делает её сам, см. выше).

**Технические особенности:**
- адрес API `platform-api2.max.ru`; на сервере нужно установить **корневой сертификат Минцифры**, иначе соединение не установится;
- лимит 30 запросов в секунду;
- с 9 сентября 2026 ограничено добавление участников в чаты через API;
- создавать и публиковать ботов могут только **верифицированные юрлица РФ**.

## 4. Где будет работать сервис

| Вариант | Как получает события | Плюсы | Минусы | Когда подходит |
|---|---|---|---|---|
| **A. Офисный компьютер или мини-ПК** | long-polling | бесплатно, без домена | выключили компьютер — поддержка молчит; доступ Claude к сервису только изнутри сети | пилот на 1–2 недели |
| **B. VPS в РФ** (Selectel, Timeweb, Yandex Cloud и т. п.) | webhook | работает 24/7, данные в РФ, недорого (~300–800 ₽/мес) | кто-то должен администрировать сервер: обновления, бэкапы | **рекомендуемый вариант для работы в продакшене** |
| **C. Облачная платформа** (Render, Fly и т. п.) | webhook | деплой одной кнопкой | серверы за рубежом, вопросы по 152-ФЗ, возможны блокировки | только если данные не персональные |

**Минимальные требования:** 1 vCPU, 1 ГБ RAM, 10 ГБ диска, Node.js 22+, сертификат Минцифры. Для вариантов B и C ещё нужен домен или поддомен с HTTPS, например `max-bot.company.ru`.

> Переписка с клиентами (имена, телефоны, тексты) — это персональные данные. Где их хранить и сколько, лучше согласовать с юристом компании. Безопасный вариант по умолчанию — сервер в РФ (вариант B).

## 6. План запуска

| Этап | Что делаем | Результат |
|---|---|---|
| 0 | Ответы на вопросы, верификация, создание бота, проверка на живом боте, что он видит в группах | токен и заполненный бриф |
| 1 | Сервис: приём событий, база, реестр чатов, MCP «только чтение» | Claude видит чаты и сообщения |
| 2 | Поддержка через группу операторов | бот поддержки работает |
| 3 | Канал: публикация, согласование, очередь, модерация | канал ведётся через сервис |
| 4 | Уведомления в группы (`/notify`), управление участниками | интеграции с сайтом и CRM |
| 5 | Деплой на сервер, вебхук, бэкапы, мониторинг | работа в продакшене 24/7 |

Стек: TypeScript, официальный SDK `@maxhub/max-bot-api`, `@modelcontextprotocol/sdk`, SQLite (позже можно перейти на Postgres), Docker.
